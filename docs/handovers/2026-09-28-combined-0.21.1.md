## Installer review (scripts/update.py, scripts/release.py)

**Sound:**

- Exact-commit, deterministic source archive with an allowlist, link/traversal/size rejection and a manifest hash per file.
- Root-only deployment directory, lock and pending journal.
- Candidate typecheck and the full isolation suite run as the service user under systemd, with state, service home, socket directory and config files made inaccessible.
- Idle checks before and after stopping the gateway and runner.
- State backed up while stopped, with ownership preserved.
- Rename swap; readiness requires the expected version **and** task schema.
- On failure, the matching application and state are rolled back together.
- Configuration fingerprints never print values.
- Codex's `8b7c4a2` correctly mirrors `mobile.ts` defaults.

**Hardened here** (`5574be9`, with tests):

1. After validation, any file outside the release manifest (other than `node_modules/`), or any link, is refused. Previously only listed files were compared, so an extra file could be deployed.
2. `plan`/`install` refuse unless the state directory and the application parent share a filesystem. Rollback `rename`s state into the backup; across filesystems it would fail midway and leave services stopped. It is satisfied on this host.

**Remaining limits** (documented by Codex, still true):

- The SHA-256 is integrity evidence, not a signature.
- Power loss is not rolled back automatically (the pending journal blocks retries).
- Backups have no retention policy yet.
